# Security

Do not place credentials, recordings, private materials or executable proofs in public issues. Report a concern privately to the repository maintainers using GitHub private vulnerability reporting if enabled. If no private channel is available, ask for a private contact without including sensitive details.

Describe the affected version, boundary, impact and a minimal synthetic reproduction. Never upload real user data. Maintainers assess whether a report is reproducible before changing published security claims.

Local tools are restricted by the host; imported documents are untrusted data. Release audits check registered files, hashes and known scanner findings. They do not establish absence of all vulnerabilities or licensing clearance. Releases require explicit human approval and are never automatically published by CI.
