# Local release procedure

Publication requires explicit human approval. These commands only create local artifacts; no push/publish/release command runs automatically.

1. Review `docs/development/release-policy.json`: runtime/source contain exact file paths, including schemas. Private plans, review evidence, writing-worker artifacts, model weights, credentials, Memanto and Agent-Bridge are absent. New code under protected roots causes a packaging error until registered. Do not add a recursive docs/tools wildcard.
2. For dependency changes, run `node scripts/dependency-inventory.mjs` and `node scripts/release-inventory.mjs`. The latter emits a candidate in test-results. Review package provenance, licenses, exact files, PDF fonts/CMaps/WASM and native binaries, then copy the reviewed candidate to `docs/development/runtime-dependencies.json`. The committed manifest is Windows x64; other distribution platforms require their own reviewed manifest. Packaging checks lock digest, platform and every file hash. Optional OCR language files, Python/venv and model weights are not bundled implicitly.
3. Run `node scripts/verify.mjs --profile pure-js`. Full UI verification uses `--profile full`. `--write-summary` copies only that actual run to `docs/verification-summary.json`; scope, failures and skips remain visible. Logs have hashes; no prebuild result is presented as postbuild evidence.
4. Set `PRACTICEBRIDGE_ELECTRON_CACHE` to a local cache containing the official pinned Windows Electron ZIP. Run `node scripts/package.mjs --out dist/BUILD-ID`. Output must be new and empty. Runtime staging copies only registered files and production dependencies. Native `.node` files and files named in the exact unpacked manifest are unpacked; worker loaders must resolve `process.resourcesPath/app.asar.unpacked/<registered path>`. Register scripts in both runtime/source and unpacked lists. No interpreter, venv or model is added. ASAR unpack selection is generated from the exact reviewed paths, including any explicitly approved non-Python companion resource. A sibling JSON read by JavaScript can remain packed; one read directly by Python must also be registered as unpacked.
5. Run `node scripts/audit-release.mjs --app dist/BUILD-ID/PracticeBridge-win32-x64`. It reads the actual ASAR and unpacked tree, then checks the whole application directory. Electron distribution files match the pinned archive; the executable's intentional metadata/icon/ASAR-integrity rewrite is separately inventoried. The manifest is local integrity evidence, not an independent signature.
6. Run `node scripts/verify.mjs --profile windows-smoke --packaged dist/BUILD-ID/PracticeBridge-win32-x64`. This exercises actual packaged Electron and synthetic audio. Human microphone and real provider checks remain unperformed until separately executed. Preserve this run's summary alongside the application. No microphone availability is counted as success.
7. Run `node scripts/release-source.mjs`, then `node scripts/audit-release.mjs --source dist/PracticeBridge-VERSION-source.zip`. Both inspect actual ZIP contents; a dist folder elsewhere in the workspace is irrelevant. Existing output is never overwritten; use `--out dist/NEW-BUILD` for another source bundle. Source files and approved synthetic assets are separate from runtime dependencies.
8. Install only the fixed development tools in `release-tools.json` into a local tools directory; validate official archive digests and extracted executable hashes. Set `PRACTICEBRIDGE_RELEASE_TOOLS` as needed. Set `PRACTICEBRIDGE_NPM_CLI` to fixed npm 12.0.1's npm-cli.js. No global installation is required. Run `node scripts/security-release.mjs --source dist/PracticeBridge-VERSION-source.zip` and `--app dist/BUILD-ID/PracticeBridge-win32-x64`. The script audits and extracts actual released content before Gitleaks and npm SBOM, then scans the SBOM with OSV. The source SBOM includes development dependencies from its actual lockfile; the runtime SBOM reflects the actual installed production tree. `--offline` requests offline OSV; missing databases or network errors remain errors, never clean results. SBOM/advisory queries concern public dependencies, not learning materials.
9. Review source/runtime inventories, scanner results, complete final-version tests, notices and checksums. Obtain human publication approval as a separate step. Keep the old downloadable release available without reusing its unverified security conclusion.

CI uses exact verified Action commits, contents:read, no secrets and no publication. Windows/Linux pure-JS jobs use synthetic materials; the Windows Electron smoke is a separate manually triggered job. CI has not run merely because this file or workflow exists.
