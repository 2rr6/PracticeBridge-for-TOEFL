# 统一机考模板

用户可以直接交给软件 PDF、文档、音频 ZIP 或文字，无需先准备 JSON。材料先保存到本机；AI 评估或本机转换后，生成这里定义的统一模板。界面按模板显示材料、题目、说明、媒体阶段与复盘内容。

题目内容集中保存在 `groups`。套题、科目与模块通过 ID 引用这些任务，不重复存放题目。内容修订形成新的 revision 和题库版本，已有题库、会话与旧作答快照保持各自版本。

## 内容版本与执行版本

```json
{
  "schemaVersion": 1,
  "version": "1.0.0",
  "examContractVersion": 1,
  "minReaderVersion": "0.3.0"
}
```

- `schemaVersion` 是题包基础结构版本；7 个基础作答类型继续使用版本 1。
- `version` 是这份材料的内容版本。修正文章、答案、题目或媒体后更新内容版本。
- `examContractVersion` 表示套题执行合同；当前支持 1。
- `minReaderVersion` 表示理解该执行合同所需的软件版本；当前模板声明 `0.3.0`。
- 提供 `examSets` 时同时提供两个执行声明。不认识的合同或交互必须明确报错，不能丢弃字段后当成普通选择题继续运行。旧题包可以省略整个执行扩展，读取时不会给旧内容补造版本声明。

正式题包的可选扩展直接省略。严格模型协议会要求这些字段出现，以 `null` 表示缺失；模型适配器先剥离可选扩展的 `null`，然后使用同一题包校验器。明确允许的可空子值，例如未知时限和未标明的原始模块号，继续保留 `null`。

## 套题、科目、模块和任务

```text
examSets[]
  └ sections[]
      └ modules[]
          ├ taskIds[] ──引用──> groups[].id
          ├ timing
          ├ navigation
          └ instructions

groups[]
  ├ 共用材料、说明、呈现与复盘原稿
  └ questions[] ──每道题只有一个永久 id
```

| 层级 | 字段 |
| --- | --- |
| 套题 | `id`、`title`、`sections`；最多 100 套 |
| 科目 | `id`、`section`、`title`、`modules`；reading/listening/speaking/writing，同套不重复 |
| 模块 | `id`、`title`、`sourceNumber`、有序 `taskIds`；可附 `timing`、`navigation`、`instructions` |
| 任务 | 原有 group 加 `taskKind`、`presentation`、`timing`、`directions`、`inlineBlanks`、`transcript` |
| 题目 | 原有 question 加 `localNumber`、`ordinalInTask`、`transcript`、`interaction`，以及原有组句句框字段 |

`sourceNumber`、`localNumber` 保存原文印出的编号，未提供时为 `null`。`ordinalInTask` 是本任务内从 1 开始的顺序。题目永久 ID、原题号和显示次序分别记录；原题号重新从 1 开始不会造成覆盖。

模块的任务 ID 必须存在，科目必须匹配。同一套执行计划不能跨模块重复引用同一道原子题目。只新增引用不会产生第二份题目内容。

## 12 个任务族与 7 个基础控件

| `taskKind` | 科目 | `questions[].type` |
| --- | --- | --- |
| `complete_words` | reading | fill_blank |
| `read_daily` | reading | single_choice |
| `read_academic` | reading | single_choice；选句/插句用 `question.interaction` 显式描述 |
| `listen_response` | listening | single_choice |
| `listen_conversation` | listening | single_choice |
| `listen_announcement` | listening | single_choice |
| `listen_talk` | listening | single_choice |
| `build_sentence` | writing | sentence_order |
| `write_email` | writing | email |
| `academic_discussion` | writing | discussion |
| `listen_repeat` | speaking | listen_repeat |
| `interview` | speaking | interview |

任务族决定材料组织与呈现流程，基础类型决定答案结构。同一段听力对应多道题时，音频属于共用任务；每题选择回应的音频则属于当前题目。不要因为底层都能用单选控件，就丢失共用材料、媒体时机或原题结构。

## 呈现、说明与原稿

`group.presentation` 可以包含：

- `screen`：`all_questions` 或 `one_question`。
- `passageVisibility`、`questionPromptVisibility`：`attempt` 或 `review`。
- `document`：`{kind,title,blocks}`。kind 为 notice/email/social_post/academic/plain；块为 `{kind:"heading"|"paragraph",text}` 或 `{kind:"table",rows:[[...]]}`。保留表格行列，不输出可执行 HTML。
- `email`：`{to,subject,instructions?,body?}`，用于带收件人、主题与任务要求的邮件写作。
- `discussion`：`{prompt,posts:[{speaker,text}],instructions?}`，用于明确的教师问题与学生观点。原文没有角色布局时，不从长段文字猜造人物。

`module.instructions` 是模块说明；`group.directions` 是任务前的有序说明数组。说明项使用 `text / audio / source / basis / verifiedContent`，directions 每项另有 `id`。至少给出说明文字或明确音频；音频属于独立说明阶段，不混入当前题目刺激音频。

`basis` 为 document/filename/user。只有文件名、未提供对应内容时，`verifiedContent` 为 false；这不等于已听取或已核实音频。没有提供的翻译、转写、姓名或图像保持缺失。

`group.transcript` 与 `question.transcript` 是题目附带的纯文字原稿，仅用于复盘。它们不是学生回答，也不表示系统听取过原始音频。作答快照分别保留对应题目原稿和题组原稿；申请反馈时与学生确认转写分开传递，反馈引文仍必须来自本次学生答案。

## 阅读正文内的缺字输入

正文中固定的词头、词尾、标点与段落由 `group.passage` 保存。每个输入框只替换明确缺失的字符范围，答案只保存学生要补入的字母。

```json
{
  "textField": "passage",
  "offsetUnit": "utf16",
  "answerMode": "missing_letters",
  "anchors": [
    {
      "questionId": "word-1",
      "localNumber": 1,
      "prefixStart": 4,
      "prefixEnd": 9,
      "start": 9,
      "end": 13,
      "missingLetterCount": 4,
      "prefix": "commu",
      "rawGap": "____",
      "source": "original.txt · line 1"
    }
  ]
}
```

这段定位对应本项目自编正文 `The commu____'s garden.`。输入 `nity` 后显示 `The community's garden.`；`commu` 和后缀 `'s` 都由原文保留。

所有位置均为 JavaScript 字符串使用的 UTF-16 半开区间：开始位置包含在内，结束位置不包含。必须满足：

- `prefixEnd === start`，并且前缀和缺字片段都逐字匹配相应正文切片。
- `start < end`，位置不越界，多个空位不重叠，题目引用正确。
- `missingLetterCount` 为 1–100，来自原文缺字标记，不根据答案长度生成空位。
- `textHash` 可以省略，由本地按实际正文计算 SHA-256；若提供就必须匹配。AI 不自行猜造哈希。
- 固定后缀在 `passage.slice(end)` 中自然保留，不要求所有缺字都处于词尾。

一个题组可能是一篇文章，也可能包含多个原子空位；题数、导航与作答记录按独立题目/空位计算。无法核实定位时保留待复核状态，不凭标准答案恢复一个看似合理的文章布局。

## 阅读选句与插句

`question.interaction` 把候选位置绑定到不可变的 `group.passage`。只用于 reading 的 read_academic/read_daily，基础类型仍为 single_choice，答案仍是一个候选 ID。

- `sentence_select`：2–30 个 `{id,start,end}` 候选，`start < end`，对应的正文切片非空；点击原句作答，不提供 `sentence` 字段。
- `sentence_insert`：恰好 4 个 `{id,start,end}` 候选，`start === end`；点击零长位置作答。可选的 `sentence` 保存题面提供的待插入原句，非空且不超过 100000 字符；省略时保留原 prompt，不自动截取或推断。
- 两种交互的 `textField` 固定为 passage，`offsetUnit` 固定为 utf16。候选 ID 唯一，按 start 严格递增，不重叠或重复，也不能越界或切开一个 Unicode 代理对。
- `options` 可以是空数组；若提供选项，ID 集合必须完整对应候选。`answer` 为 null 或一个已有候选 ID；不接受多选答案数组。
- `textHash` 可省略，由本地计算；提供错误哈希会阻断导入。候选随题目切换，选择后的插句预览不修改原正文，也不影响同组其他题目。

以下插入位置对应本项目自编正文 `🌿 A quiet path crosses the park. Rain fills a small pond. Birds rest near the water. Shade keeps the path cool.`。位置包含开头 emoji 占用的两个 UTF-16 单元：

```json
{
  "kind": "sentence_insert",
  "textField": "passage",
  "offsetUnit": "utf16",
  "candidates": [
    { "id": "A", "start": 0, "end": 0 },
    { "id": "B", "start": 34, "end": 34 },
    { "id": "C", "start": 59, "end": 59 },
    { "id": "D", "start": 86, "end": 86 }
  ],
  "sentence": "The pond also supports insects."
}
```

位置有效只证明范围可以使用，不能证明它就是原题候选。AI 整理还要核对原材料中的明确标记；目前可识别完整正文中的 `##`、方块、带候选 ID 的括号及成对句子标记。无标签的四个插入点按 A–D 原文顺序对应。无法核实标记时保留复核错误，不把交互改成普通选项列表。未支持的交互种类明确报错。

## 计时与导航

计时对象为 `{scope,durationSeconds,prepareSeconds,basis,source}`：

- scope：module/task/question/none；任务还可以 `inherit_module`。
- durationSeconds：1–7200 的整数或 null。prepareSeconds：0–7200 或 null。
- basis：document/user/preset/unknown；source 保存依据。
- 未提供明确数字和单位时保留 null，不能填印象中的官方时间。原文写 2 minutes 可以明确换算成 120 seconds。
- `inherit_module` 不把模块时间复制到每题。归一化后仍保留完整计时对象。
- 旧题目 `timeLimitSeconds` 的 0 表示不计时，兼容旧练习；它不是一个新推断的官方时限。

导航对象为 `{back,review,lockOnAdvance}`，back/review 为 module/task/none。没有明确来源或用户设置时可省略，使用本机已定义的练习流程。模板版本固定后，当前会话不会因题库重新整理而改变导航或计时。

## AI 输出与内容更新

整理器应输出稳定 ID、明确任务族、来源位置、题目原文、可核实的布局、显式媒体关联与缺项提示。只复制给出的答案键；没有答案就保留不计分状态。无法表达的原生交互必须报错，不能丢字段后伪装成另一种题目。

本项目对飞马本地结构的只读观察确认了套题/科目/模块/题组/题目的关系、12 个任务族、正文填空和不同材料布局。所查看的更新包包含媒体与一个非普通 SQLite 的题库容器，没有独立可套用的 JSON/SQL 源模板；容器内部更新细节未解读。PracticeBridge 采用同样的模板驱动原则，使用自己的公开数据结构，不声称能直接读取该私有题库。

数据修订、AI 重新整理和题库发布都应产生新内容版本。旧 library、旧 session 及旧答案快照继续引用当时内容，不能被新题库覆盖。

机器可读字段见 [practicebridge.schema.json](practicebridge.schema.json)。输入入口和兼容规则见 [输入格式.md](输入格式.md)。
