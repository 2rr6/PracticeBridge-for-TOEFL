# PracticeBridge 文案规则

用朴素中文说明一个具体操作及其结果。读者应能分清保存材料、整理候选、核对来源、开始练习、回看反馈这几个动作。先让第一次使用的人知道从哪里开始，不把内部模块名和实施任务号放进普通用户流程。

短段落优先。只有真正并列或需要逐步执行的信息才用列表；功能比较可以用简短表格。不要每句话都另起一行，不堆口号，不虚构学习者故事、采用规模或节省时间的数据。

保留界面中的 PRACTICE、TEST、Original / Retry 等实际标签。技术术语只在有助于操作时出现：例如解释数据目录或模型地址时可以写路径/参数，介绍练习体验时不需要讲存储事务和 worker。中文标题用自然名词或动词，不用“赋能”“无缝”“革命性”“一站式”“释放潜能”等宣传措辞。

事实和程度词一起审查。“保存到本机”不能润色为“绝对隐私”，“已检查结构”不能润色为“准确识别”，“一台 Windows 电脑上验证”不能写成“跨平台稳定”，“使用自己的服务”不能写成“免费 AI”。不要使用没有证据的“全面支持”“完美导入”“官方准确率”或“零风险”。

限制应放在相关功能附近，用一句可操作的话说明缺什么、在哪里核对或下一步怎么办。不要删除收费、来源、模型能力和人工确认的限定。可以说“没有标准答案的题目不计入客观正确率”，不要把未知答案或识别失败改写成用户答错。

示例只用明确自编的普通内容。不复制题库、真人录音、账户信息或测试证据中的个人细节。所有命令、版本、能力和来源声明必须能在事实包中找到对应 ID。文案工作只改变表达，不能扩大功能或数据权限。
